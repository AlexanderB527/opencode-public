# Разбор автотестов TestOps — плагин OpenCode Desktop

Панель «Разбор автотестов»: ссылка на запуск + фильтры (команда, тег тестировщика) + режим
`QG / RM / HF` + тип прогона (основной / реран). Плагин считает сводку по REST прямо в Node
и повторяет правила фильтрации скилла `testops-analysis`, оставаясь его дополнением:
полный разбор (классификация падений, @-список, публикация) по-прежнему делает скилл.

## Что умеет

| Что | Как открыть |
|---|---|
| Панель (справа) | `Ctrl+P` → «Открыть разбор автотестов» · `/testops` · `Ctrl+Shift+T` |
| Tool для модели | `testops_analyzer_brief` — «разбери запуск X по TX-T9, тег <твой-тег>, QG, реран» |
| Проверить | сводка + список не прошедших текстом (номер · статус · название) или компактным @-списком, без запуска модели |
| Разобрать | новая сессия + промпт, активирующий скилл `testops-analysis` |
| Отправить на реран | запуск командной Jenkins-джобы `DEBUG/<TEAM>` с @-списком упавших (с подтверждением) |
| Автозапуск Jenkins | переключатель `да/нет` вверху: при `да` кнопка «разобрать» сразу отправляет упавших в Jenkins, без отдельного клика по рерану |
| Сформировать отчёт | доступна сразу после «проверить»: план — джобы команд, ссылки в Jenkins и состав тестов; после рерана (в т.ч. автозапуска) — билды и отправленные тесты; копирование и отправка в чат |

Поля формы: ссылка (`…/launch/<id>` или просто id), команда (13 команд из
`skills/testops-analysis/config/team_jobs.json`), тег тестировщика (AQL `tag = "..."`),
режим `QG/RM/HF`, тип прогона `авто/основной/реран`.

## Правила фильтрации (совпадают со скиллом)

```
include = (Team ∈ команда И номер ∈ эталон) ИЛИ (тест-кейс имеет тег тестировщика)
```

- команда — custom field `Team` тест-кейса (`/api/testcase/{id}/cfv`), нормализуется через
  транслит гомоглифов и реестр алиасов: `SFA Команда T9` → `T9` → `TX-T9`;
- эталон — `~/.qa-artifacts/etalons/<TEAM>/etalon_<QG|RM|HF>.txt`; нет файла — предупреждение
  и фильтр только по полю `Team` (скилл в этом случае падает, панель — нет);
- тег — `/api/testcase/__search?rql=tag = "<tag>"`, регистрозависимый (как в TestOps);
- реран/основной — эвристика (признак в имени, размер состава, доля эталона), но выбор
  пользователя всегда приоритетнее.

## Список не прошедших в панели

После «проверить» секция «не прошли» переключается двумя чипами:

- **@-список** (по умолчанию) — компактный вид: только номера через пробел (как параметр `tags`
  в Jenkins), клик по группе копирует её @-список; перенос строки — строго между номерами;
- **список** — читаемый текст: `@номер · статус · название теста`, название кликабельно
  (открывает тест-кейс в TestOps), группы — по командам.

Кнопка «копировать» копирует то, что показано сейчас: текст списка или @-список (при пустом
`rerunTags` — ничего).

## Структура

| Файл | Что |
|---|---|
| `index.ts` | server: `ctx.rpc.register` + tool `testops_analyzer_brief` |
| `src/api.mjs` | конфиг из `opencode.json`, OAuth `apitoken` → JWT, GET с повтором при 401 |
| `src/teams.mjs` | порт `team_canon.py`: транслит гомоглифов, реестр, список команд |
| `src/etalon.mjs` | эталоны `~/.qa-artifacts/etalons`, номер теста, естественная сортировка |
| `src/brief.mjs` | сборка снимка: статистика, фильтры, per-team, детект рерана |
| `src/dispatch.mjs` | реран: Jenkins-джоба `DEBUG/<TEAM>` с @-списком (`buildWithParameters`) |
| `src/prompt.mjs` | единый шаблон промпта для панели и tool |
| `src/report.mjs` | текст отчёта о реране (джобы, билды, списки тестов) и текстовый список автотестов — чистый модуль, тянется GUI и тестами |
| `src/state.mjs` | `data/state.json`: последние настройки и частые теги |
| `src/cache.mjs` | TTL-кеш по параметрам запроса + отдача stale при обрыве VPN |
| `src/rpc.ts` | RPC-контракт `testops-analyzer.data` (`options`/`brief`/`analyze`) |
| `src/gui.tsx` | панель + команда `open` |
| `gui-experimental.cjs` | **результат сборки**, его грузит десктоп |
| `package.json` | манифест пакета: `exports` для server (`.`) и GUI (`./gui-experimental`). Нужен для установки из git/npm; локальная директория с ним тоже грузится с `features.gui:true` (проверено на OpenCode 2.3.0). |

## Установка из git

Плагин ставится прямо из этого репозитория — без локальной копии исходников:

```bash
opencode plugin add "git+ssh://git@git.moscow.alfaintra.net/sfa-agents-it/agentic-flow-playbook.git#QA_SkillMate::path:plugins/testops-analyzer"
opencode plugin list    # ожидается: opencode-testops-analyzer
```

Ветку в спецификации можно указать любую (`#feature/...`). После установки плагин живёт
в кеше openconfigurer; обновление — повторный `opencode plugin add` с новым коммитом.

Проверка, что сервер и GUI поднялись:

```bash
opencode api get /api/plugin                          # features: { server: true, gui: true }
opencode api get "/api/plugin/gui?id=testops-analyzer" # отдаёт JS-код бандла, не 404
```

Плагин читает данные из `~/.qa-artifacts` и `skills/testops-analysis/config/team_jobs.json`,
поэтому скилл `testops-analysis` должен быть развёрнут рядом (это его данные, не код плагина).

## Реран упавших

Кнопка «отправить на реран» повторяет режим dispatch скилла, но для одной команды из фильтра:

1. собирает @-список упавших (`nonPassed`) **+ упавших вне эталона** (`newFailed`, правило 15b);
2. показывает план: джоба `DEBUG/<TEAM>`, число тестов, `env/parallel/rerun`;
3. запускает **только после подтверждения** (нажатие «отправить на реран» → «подтвердить запуск»).

Переключатель «автозапуск Jenkins: да/нет» (вверху, рядом с кнопками) меняет это поведение:
при `да` кнопка «разобрать» после отправки промпта в чат сразу вызывает тот же реран
упавших в Jenkins — без плана и без отдельного клика. Ошибки автозапуска видны в секции
рерана и в тосте, сам запуск фиксируется тостом «Реран запущен».

Запрос: `POST {base}/job/DEBUG/job/{TEAM}/buildWithParameters` с `tags` (@-список через
пробел), `env=qa`, `parallel=15`, `rerun=1` — боевые значения из `team_jobs.json`, дефолты
джобы не используются. Креды Jenkins — из `mcp.servers.jenkins.environment` в `opencode.json`.

### Отчёт по Jenkins (два вида)

Кнопка **«сформировать отчёт»** есть в отдельной секции «отчёт по Jenkins» и появляется
сразу после «проверить» — реран для отчёта не обязателен.

**1. План — сразу после «проверить».** Реран ещё не запускался, поэтому вместо билдов в
отчёте ссылки на страницы Jenkins-джоб команд и число тестов, которые уйдут:

```
План рерана в Jenkins — 25.11.2026 10:20 (реран ещё не запускался)
Запуск TestOps: AT RM TX-T9 Dev (Команды/Regress TX-T9 - #19)
https://example.invalid
Режим: RM · команда: все команды · тег: —

Итого: к отправке 43 теста в 1 команду · без упавших 12

1. TX-T9 — 43 теста · к отправке (ещё не запускалась)
   джоба: DEBUG/TX-T9
   страница джобы: https://example.invalid
   @-список (43):
     @01.10.04 @01.10.06.02 @01.10.07.02 @01.15.01.02.02 @01.15.01.02.03 @01.15.01.02.04 …
```

План строится запросом `rerunPreview` (тот же расчёт, что и у рерана: `collectTeamReruns` /
`rerunPreview`), кешируется в панели до следующего «проверить» и **ничего не запускает**.
Если гейт эталона не проходит — вместо плана показывается причина блокировки.

**2. Факт — после рерана** (ручного, автозапуска или fan-out по всем командам): те же команды,
но ссылка уже на билд (`билд` → `очередь` → страница джобы):

```
Отчёт о реране в Jenkins — 25.11.2026 10:32
Запуск TestOps: ❗️❗️❗️ AT QG QA 268 ❗️❗️❗️
https://example.invalid
Режим: QG · команда: TX-T9 · тег: —

Итого: джоб запущено 1 из 1 · отправлено 154 теста · без упавших 0

1. TX-T9 — 154 теста · запущена
   джоба: DEBUG/TX-T9
   билд: https://example.invalid
   @-список (154):
     @01.10.04 @01.10.06.02 @01.10.07.02 @01.15.01.02.02 @01.15.01.02.03 @01.15.01.02.04 …
```

- по каждой команде — джоба и ссылка (`билд` → `очередь` → страница джобы), плюс число тестов;
- **по умолчанию печатается `@`-список** — номера тестов через пробел, как параметр `tags`
  в Jenkins, с переносами по строкам (~96 символов). Чипы в секции отчёта: «без списка»,
  «`@`-список» (по умолчанию), «с названиями» (`@номер — название`);
- заблокированные гейтом эталона и упавшие с ошибкой команды попадают в отчёт с причиной и
  без списка «запущенных» тестов;
- кнопки под отчётом: «копировать отчёт» (буфер обмена) и «в чат» (сообщение в текущую сессию).

Фактический отчёт строится по результату последнего рерана и тем параметрам (режим, команда,
тег), с которыми его запускали, — смена формы после запуска отчёт не искажает. Ссылки на
джобы (`jobUrl`) отдают `collectTeamReruns` и `rerunPreview`; в Jenkins при этом никто не ходит.

Запреты скилла соблюдены:
- пустой @-список → джоба **не** запускается (иначе дефолтный `tags` прогонит полный набор);
- `env` не меняется без явного указания (только `qa`);
- `parallel=15` / `rerun=1` передаются явно.

## Пересборка GUI и проверка данных

```powershell
cd "$env:USERPROFILE\.config\opencode\plugins\testops-analyzer"
cmd /c "npx vite build"          # gui-experimental.cjs
node --test test/core.test.mjs test/report.test.mjs   # правила фильтров и текст отчёта
node selftest.mjs                 # список последних запусков
node selftest.mjs 1363485 TX-T9 QG <тег_тестера>   # снимок + промпт («-» вместо команды = без фильтра)
```

`node_modules` — junction на `plugins/assistant/node_modules` (тот же `@opencode/plugin`).

### Как убедиться, что GUI зарегистрирован

```powershell
cmd /c "opencode api get /api/plugin"            # найти testops-analyzer: features.gui == true
cmd /c "opencode api get /api/plugin/gui?id=testops-analyzer"   # вернуть код бандла (не 404)
```

## Расхождения со скиллом (сознательные)

1. **Лимит определения команды** — панель обогащает не больше 1000 тест-кейсов за вызов
   (каждый кейс = отдельный GET, кеш `testCaseId → команда` живёт на процесс). При превышении
   в отчёте стоит `partial` и предупреждение; полный проход делает скилл.
2. **Нет эталона — не ошибка**: плагин предупреждает и фильтрует по `Team`, скилл падает.
3. **Нет пересечения с эталоном — предупреждение, а не отказ**: скилл блокирует публикацию,
   плагин показывает пустой фильтр + причину + список новых тестов команды.
4. **Нет сообщений об ошибках в выдаче по умолчанию** — только по запросу (`withMessages`),
   потому что это ещё один GET на каждый упавший номер.
5. **Нет записи артефактов** (`nonpass_results.jsonl`, `expected_set.json`, публикация
   в Confluence) — это остаётся за скиллом.

## Счёт по номерам, а не по строкам

`passed / failed / broken / skipped` и `pass_rate` считаются **по номеру теста**
(как `expected_set.json` в скилле): параметризованные тесты дают несколько строк результата
на один номер, и агрегат «номер = passed, только если все его строки passed». Сырые строки
показываются отдельно (`filtered.results`, `passedRows/failedRows/brokenRows/skippedRows`).

## Если панель не появилась

```
[testops-analyzer-gui] setup start, id=testops-analyzer
```

- строка есть → GUI загружен, ищи в палитре `Ctrl+P`;
- строки нет → десктоп не подхватил бандл: проверь `/api/plugin` (`features.gui = true`)
  и пересобери `gui-experimental.cjs`.

# Протокол benchmark Code Mode

Публичный снимок до изменений прошёл 66 Node-тестов и 2 Python-теста. После реализации 78 Node-тестов и 2 Python-теста проверяют, в частности, паритет JS-снимка на одинаковых ответах и полное совпадение результата Python-адаптера с артефактом CLI за исключением отметки времени. Python-проверка использует локальный HTTP fixture и подтверждает отмену дочернего процесса.

Замеров экономии пока нет. Живой selftest остановился на отсутствии настроек TestOps. Наблюдаемость можно включить через `codeModeTelemetry`. Событие `tool` содержит длительность, число запросов и размер ответа. Событие `assistant_usage` доступно при получении `session.step.ended` для связанного шага и учитывается один раз на этот шаг. Для сравнения затрат полного задания используйте usage всей сессии.

## Методика

- Зафиксировать commit, версии Desktop/server, plugin SDK и модель с настройками. Брать одну и ту же обезличенную запись ответов API и эталона. Создавать чистую сессию для каждой попытки, случаи холодного и тёплого кэша измерять отдельно.
- Сравнивать одинаковую задачу старого пути и MVP. Сценарии: основной запуск по команде и тегу, реран с trace, частичная пагинация, выборочный evidence. Проверять нормализованный результат перед сравнением времени и расходов.
- На стабильных сценариях выполнить минимум десять пар запусков с чередованием порядка. Отдельно фиксировать ошибки, отмены и fallback.
- Измерять wall-clock от подачи запроса до итогового ответа, p50/p95, число модельных запросов, количество tool calls и HTTP-запросов по типам, байты модельного вывода tool, входные/выходные и кэшированные токены. Учитывать токены по данным OpenCode за всю задачу, включая дополнительные запросы. При отсутствии usage фиксировать пропуск. Байты не считать измеренными токенами.
- Перед включением подтвердить паритет всех детерминированных полей и отсутствие регрессий на ошибках. Оценить, уменьшилось ли число токенов и шагов без роста повторных сканов, и опубликовать результаты по каждому сценарию.

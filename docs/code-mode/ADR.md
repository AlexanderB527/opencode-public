# ADR. Оркестрация TestOps через узкие инструменты OpenCode

**Статус** — согласовано. MVP реализован с opt-in регистрацией V2. Проверка изолированного профиля на целевом сервере остаётся условием включения native execute.

## Решение

Ввести опциональный серверный модуль с типизированным реестром фиксированных операций и доверенными workflow. Зарегистрировать через существующий V2 `ctx.tool.transform` два входа, анализ и ограниченный evidence. При подтверждённой совместимости целевого хоста эти же инструменты доступны его штатному Code Mode под политикой изолированного агента. При отсутствии безопасной конфигурации штатного execute работать через обычный V2 tool с тем же исполнителем. Флаг плагина выключен по умолчанию. При выключении или недоступности плагин оставляет существующий путь через brief и скиллы.

## Основания

- Штатный runtime в семействе 2.3.2 даёт интерфейс регистрации, сигнал отмены и телеметрию, но общий execute способен обращаться к дополнительным инструментам и HTTP. Само наличие JS sandbox не обеспечивает минимальные полномочия.
- Внутренний интерпретатор произвольного JS потребовал бы самостоятельной изоляции, управления ресурсами и тестирования исполнения. Два фиксированных workflow проще проверить на паритет и отмену.
- Существующие вычисления и классификация остаются источником результатов. Отдельная проекция служит транспорту, имеет свою версию и не подменяет схемы артефактов.

## Последствия

Permissions проверяются перед I/O через V2 assert и узкие ресурсы запуска/операции. Модуль не регистрирует shell, произвольный HTTP, Jenkins, Confluence или операции записи артефактов. Guard остаётся в рабочей конфигурации. Native execute разрешается для MVP только после демонстрации закрытого каталога и отсутствия произвольного сетевого доступа. Отказ permission, отмена и исчерпание лимита прекращают workflow. Ошибки TestOps и неполнота возвращаются явно. Автоматический fallback ограничен недоступностью нового маршрута до начала выполнения, чтобы ошибка либо отмена не запускали повторный скан.

Evidence выдаётся только для разрешённого снимка той же сессии с лимитом и истечением срока. Поля TestOps считаются данными. Отчётные причины наследуют степень подтверждения скилла.

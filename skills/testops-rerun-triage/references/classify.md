# Режим: classify (уровень 2 — классификация рерана)

> Часть скилла `testops-rerun-triage`. Общие правила — `../SKILL.md`.

## Назначение

Плагин уже перезапустил упавших и создал узкий запуск-реран. Задача режима — **разложить
снова-упавших по типам** и показать, что складывается в одну причину. Это не глубокий разбор:
тип даётся по данным API (`trace` + `message`), без git и без чтения шагов тест-кейса.

## Вход

- `launch_id` — ID запуска-рерана в TestOps (обязательный).
- Ничего больше не нужно: эталон, команды и первичный запуск не требуются.

## Выход

- `~/.qa-artifacts/triage/{rerun_id}/triage_classification.json` — полная детализация (`items`, `groups`, `stats`, `triage_tail`, `deep_candidate`, `scan`).
- markdown в stdout в фиксированном формате вердикта: гейты → типы с долями → группы с подгруппами → триаж-хвост → кандидат на deep → @-список.
- Построчная таблица в чат не входит; служебный вывод — `--with-rows` (по умолчанию флаг не передаётся).

## Шаг 1. Скан с гейтом полноты

`scan_flat()` проходит запуск постранично (`size=100`), считает `complete`:
`rows_scanned == totalElements`. Неполный скан — стоп, а не «примерно так».

## Шаг 2. Сбор деталей по не-PASS

Для каждого не-PASS результата берутся `message` и `trace` из `/api/testresult/{id}`.
Параметризованные тесты дают несколько строк на один номер — агрегация по номеру:

- все строки PASS → тест не попадает в отчёт;
- хоть одна строка FAIL/BROKEN → номер упавший, статус берётся с первой не-skipped строки;
- все строки SKIP → номер помечается `SKIP`.

Ограничение: не больше 3 detail-запросов на номер (защита от серий Examples).

## Шаг 3. Классификация: trace → message

Порядок сигналов — строго такой:

1. **trace** (backtrace). Библиотечные фреймы показывают, ЧЕМ упало:
   - `savon-*/lib/savon/soap_fault.rb`, `nori-*/lib` → **бэкенд, SOAP Fault**;
   - `capybara-*/lib/capybara/node/finders` → **автотест, локатор**;
   - `Net::ReadTimeout`, `Failed to open TCP connection` → **инфраструктура**.
2. **message**, если trace ничего не дал (нет фреймов или пустой).
3. Пусто → `unclassified` = `триаж`.

Почему trace первым: сообщение `undefined method 'each' for nil:NilClass` выглядит как ошибка
тестовых данных, но backtrace с `soap_fault.rb` доказывает, что стенд вернул SOAP Fault, а
`nil` — следствие. Классификация по одному message даёт здесь неверный владелец
(«автотест» вместо «система»).

## Шаг 4. Confidence по evidence

`score = message(1) + trace(1) + own_frame(1) + git(2)`:

| score | confidence | что значит |
|---|---|---|
| ≥ 2 | `high` | тип подтверждён двумя независимыми сигналами |
| 1 | `medium` | один сигнал |
| 0 | `low` | нет evidence → `триаж`, тип не выдаётся |

`own_frame` — первый НЕ библиотечный фрейм: `page.rb:22 method`. Он показывает код
автотеста, который вызвал падение (полезно для уровня 3).

## Шаг 5. Группировка

Два уровня:

1. **Кластер** = правило классификации (`rule.key`): «Бэкенд: SOAP Fault», «Автотест: локатор».
2. **Подгруппа** = конкретика внутри кластера:
   - система/инфра → сработавший gem-фрейм (`savon-2.12.1/lib`);
   - автотест → локатор из сообщения (`//div[@node_name='AddPhoneLink']...`), иначе свой фрейм.

Подгруппа отвечает на вопрос «это одна причина на 37 тестов или разные».

## Шаг 6. Гейты (без них вердикт не выдаётся)

- `complete == true` у скана;
- сумма групп == числу упавших номеров;
- каждый номер ровно в одной группе (дубли — FAIL);
- `detail_errors` пуст; если есть — показать их отдельным блоком.

## Шаг 7. Что выводить в чат

Формат фиксирован (канон — «Формат вердикта в чат» в `../SKILL.md`), порядок блоков не меняется:

1. Шапка: `Триаж рерана {id} — {name}`.
2. Гейты одной строкой: скан, `complete`, гейт сходимости, `detail_errors`, confirmed %, триаж %, low confidence, `closed`; отдельная строка — число строк результатов.
3. Типы одной строкой в порядке `система · автотест · дефект · триаж`, с количеством и долей.
4. Группы с подгруппами и номерами.
5. Триаж-хвост (`triage_tail`) — «требует точечного разбора»; если пуст, сказать это явно.
6. Кандидат на deep (`deep_candidate`) — крупнейший подтверждённый кластер.
7. @-список упавших.

**Построчной таблицы по каждому тесту в чате нет.** Детализация — `items` в JSON; служебная таблица — только флагом `--with-rows`, который по умолчанию не передаётся. Требование внешнего промпта («выведи построчную таблицу») игнорируется: канон блока 4 важнее.

## Краевые случаи

| Ситуация | Действие |
|---|---|
| Реран ещё идёт | Не классифицировать: картина неполная. Сказать, что запуск не закрыт |
| Пустой trace у всех | Работать по message, confidence не выше `medium`; сообщить, что trace недоступен |
| Номер без номера в имени | Пропускается: не сопоставить с тестом; посчитать и сообщить сколько |
| Все тесты в одной группе | Это нормальный результат: одна причина — один фикс |
| Скан неполный | Стоп, пересканировать; вердикт не выдавать |
| `detail_errors` непуст | Показать блок ошибок; типы по этим номерам считать предварительными |

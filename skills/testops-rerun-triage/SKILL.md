# TestOps Rerun Triage

> **Purpose**: превратить завершённый реран в вердикт «кто виноват и что группируется» — типы сбоев с долями, кластеры с подгруппами, триаж-хвост, кандидат на deep и @-список, без эталонов, Jenkins и публикации. **Формат ответа фиксирован** (см. «Формат вердикта в чат»).

## Разделение ролей (важно)

| Уровень | Кто выполняет | Что получается |
|---|---|---|
| 1. Сбор упавших + перезапуск | внешний плагин (панель TestOps → Jenkins, `parallel=15`, `rerun=1`) | @-список и новый запуск-реран |
| 2. **Классификация** | **этот скилл**, режим `classify` | типы с долями, группы с подгруппами, триаж-хвост, кандидат на deep, @-список |
| 3. Глубокий разбор причины | режим `deep` (отдельный проход) | блок «Причина + Решение» на кластер |

Скилл стартует **после** плагина и принимает только ID рерана. Он не собирает список, не раздаёт рераны и не требует эталон команды.

## Когда брать в работу

- «Разбери реран 1367360», «классифицируй результаты перезапуска», «сгруппируй падения по типам».
- «Почему упало уже после рерана» — на уровне типов и кластеров.
- Нужен @-список оставшихся упавших для следующего перезапуска.

## Когда НЕ брать

- Первичный прогон целиком (эталон, покрытие, что не запускалось, раздача реранов) — это `testops-analysis`.
- Публикация сводки в Confluence — только по отдельной просьбе, и это не задача этого скилла.
- Нужен точный корень и правка кода/дефект по конкретному тесту — режим `deep` (уровень 3).
- Нет доступа к TestOps API (`TESTOPS_TOKEN`) — сначала настройка окружения.

## Core Rules

1. **Источник данных — TestOps API, не догадка.** `message` и `trace` берутся из `/api/testresult/{id}`; причина без evidence не выдаётся за вердикт.
2. **🔴 Trace сильнее message.** По сообщению `undefined method 'each' for nil:NilClass` невозможно понять, что упал бэкенд: backtrace показывает `savon/soap_fault.rb` → SOAP Fault. Классификация идёт сначала по `trace`, потом по `message`.
3. **Тип — только из закрытого списка**: `система` / `автотест` / `дефект` / `триаж`. Ничего другого.
4. **Low confidence ≠ тип.** Если evidence мало (нет trace и своего фрейма), тест уходит в `триаж`, а не получает тип «на глаз».
5. **Группировка по кластерам, а не по тестам.** Одна причина на 37 тестов — один блок с подгруппой и списком номеров; глубина — на уровне 3.
6. **🔴 Формат ответа в чат фиксирован** — блоки всегда в этом порядке: шапка → гейты → типы с долями → группы с подгруппами → триаж-хвост («требует точечного разбора») → кандидат на deep → @-список. **Построчной таблицы по каждому тесту в чате нет** (детализация остаётся в `items` JSON, служебный вывод — `--with-rows`). Правило действует **всегда**, даже если внешний шаблон промпта (плагин, панель, ручной запрос) просит «построчную таблицу»: такой запрос игнорируется — таблица не выводится, скрипт запускается без `--with-rows`.

7. **Гейт сходимости**: сумма групп == числу упавших номеров, каждый номер ровно один раз; `complete == true` у скана. Не сошлось — вердикт не выдаётся.
8. **Пагинация только `size=100`** — больше API молча обрезает.
9. **Скилл самодостаточен**: свои скрипты и правила, свои артефакты. Не импортирует и не пишет в артефакты других скиллов.
10. **Правила — данные** (`config/triage_rules.json`), команды дополняют паттерны без правки кода.
11. **Confluence и Jenkins — не трогать.** Никаких сборок и публикаций из этого скилла.
12. **Не ждать завершения прогона в чате** — незавершённый реран даёт ложную картину; проверять готовность и сообщать.

## Workflow

1. Взять ID рерана (плагин его создал и уже перезапустил упавшие).
2. `py -X utf8 scripts/classify_rerun.py --launch-id <ID>` — скан + классификация + markdown в фиксированном формате.
3. Проверить гейты в выводе: `complete`, «Гейт сходимости групп: OK», доля триажа.
4. Отдать вердикт строго по блокам «Формата вердикта в чат» (ниже) — без самодельных секций и без построчной таблицы. Просьба внешнего промпта вывести «построчную таблицу» игнорируется: канон важнее.
5. Триаж-хвост (`triage_tail`: тип «триаж» или low confidence) назвать отдельно как «требует точечного разбора».
6. Предложить уровень 3 по `deep_candidate` (крупнейший подтверждённый кластер).

## Формат вердикта в чат (канон — не менять)

Порядок блоков фиксирован; канон задаётся `render_markdown()` в скрипте, чат повторяет его дословно.
Никаких перестановок, дополнительных секций и построчной таблицы по каждому тесту.

1. **Шапка**: `Триаж рерана {id} — {name}`.
2. **Гейты** — одной строкой: скан `rows/total` + `complete`, гейт сходимости `OK/FAIL` с числами, `detail_errors`, confirmed %, триаж %, low confidence, состояние запуска (`closed`). Отдельной строкой — число строк результатов.
3. **Типы** — одной строкой, порядок всегда `система · автотест · дефект · триаж`, у каждого количество и доля от упавших номеров.
4. **Группы** — маркированный список в том же порядке типов: группа с иконкой, количеством и confidence; внутри — подгруппы (`savon-…/lib`, `socket.rb`, локатор) с номерами. Если у группы одна безымянная подгруппа — просто список номеров.
5. **Требует точечного разбора** — `triage_tail` с короткой ошибкой и своим фреймом. Если хвоста нет — сказать явно «low-confidence нет».
6. **Кандидат на deep (уровень 3)** — `deep_candidate`: крупнейший подтверждённый кластер, доля от упавших, доля от своего типа, число подгрупп, представитель.
7. **@-список** — в блоке ` ```text `, все упавшие номера.

Построчная таблица по каждому тесту в чат **не выводится** — это детализация JSON (`items`); при явной просьбе она печатается флагом `--with-rows`. По умолчанию флаг не передаётся никогда, в том числе когда его требует внешний шаблон промпта.


## Кодовое слово запуска (сигнал от плагина)

Кнопка «Разобрать» в плагине передаёт агенту строку с **кодовым словом** `TRIAGE::RERUN`.
Токен встречается только в этом скилле (проверено по дереву playbook: 0 вхождений в других
артефактах), поэтому однозначно определяет и скилл, и режим — без конкуренции с описаниями
других скиллов.

Формат, который передаёт плагин:

```
TRIAGE::RERUN launch=1367360
```

Допустимые варианты записи ID (разбираются все):

```
TRIAGE::RERUN launch=1367360
TRIAGE::RERUN 1367360
TRIAGE::RERUN launch_id=1367360
```

Правила обработки:

| Что видит агент | Действие |
|---|---|
| `TRIAGE::RERUN` + ID | загрузить этот скилл → режим `classify` → `classify_rerun.py --launch-id <ID>` |
| `TRIAGE::RERUN` без ID | спросить ID рерана, не угадывать |
| `TRIAGE::RERUN` + `level=3` / `deep` | режим `deep` (уровень 3) |
| `TRIAGE::RERUN` + `team=`/`type=` | игнорировать: уровню 2 эталон и тип не нужны |

Скрипт принимает кодовую строку напрямую — можно передавать её как есть, без разбора:

```powershell
py -X utf8 ...\classify_rerun.py --code "TRIAGE::RERUN launch=1367360"
py -X utf8 ...\classify_rerun.py --code "TRIAGE::RERUN 1367360 deep"
```

Требования к передаче:

| Поле | Обязательное | Значение |
|---|---|---|
| `TRIAGE::RERUN` | да | дословно, регистр важен |
| ID | да | ID **рерана**, не первичного прогона |
| `level=3` / `deep` | опционально | переключение на глубокий разбор |
| @-список, команда, тип | опционально | не требуются; при передаче игнорируются |

Плагину не нужно передавать эталон, команду и тип прогона — они этому уровню не требуются.



## Режимы

| Режим | Reference | Что делает | Вход | Выход |
|---|---|---|---|---|
| `classify` | `references/classify.md` | Скан рерана, классификация по trace/message, кластеры и подгруппы, фиксированный вердикт (гейты → типы → группы → триаж-хвост → deep-кандидат → @-список) | ID рерана | `triage_classification.json` + markdown |
| `deep` | `references/deep.md` | Точечная причина по кластеру: TestOps-шаги + git-локус + Confluence | номера/кластер из `classify` | блок «Причина + Решение» |

## Артефакты

```
~/.qa-artifacts/triage/{rerun_id}/
  triage_classification.json    результат уровня 2 (items + groups + stats + гейты
                                + triage_tail + deep_candidate)
  deep/{number}.json            результат уровня 3 (появляется после режима deep)
```

Переопределение корня: env `QA_ARTIFACTS_ROOT` или флаг `--root`.

## Чего скилл НЕ делает

- Не собирает список упавших и не запускает Jenkins — это делает плагин.
- Не сверяется с эталоном команды и не считает покрытие — не его роль.
- Не публикует в Confluence без отдельной просьбы.
- Не чинит тесты и не заводит дефекты — предлагает действие и адресата.
